# Trial 2026-09-11: PRD v4 runtime, Claude Code `-p`, Sonnet

Focused live trials of the PRD v4 runtime from the packed candidate kit, plus a bounded
comparison of two scenarios on the v0.4.1 baseline kit. One `claude -p --model sonnet
--permission-mode bypassPermissions` session per stage or scenario (`env -u CLAUDECODE`,
stdin from `/dev/null`), with an operator terminal auditing on disk between sessions.
This is one surface (Claude Code print mode, Sonnet, macOS); it says nothing about
Codex, Copilot, the plugin install, Windows or Node 18.

- Brief (greenfield, session A1): "Build a tiny dependency-free Node.js CLI called
  notes: `node notes.js add <text>` appends a note to notes.json in the repo root and
  `node notes.js list` prints the stored notes one per line in insertion order. Tests
  use node:test and run with `npm test`. Assumptions you may record instead of asking:
  profile small; no budget; no UI; done means npm test passes and both commands work
  from a fresh clone; invalid input (add without text) exits 1 with a one-line message.
  Do not ask me questions; record the assumptions in the PRD and commit it."

## Interventions

1. Greenfield fixture from the candidate tarball (`pincer init --platform claude`, commit `79e240e`).
2. Prompts as quoted above; A2–A5 received only the playbook command.
3. Kit re-pack and `pincer update` in the greenfield fixture between A3 and A4 (commit `7fb4de4`), because A3 exposed the T-43 defect (see findings); this update commit touched the runtime's tracked files, so status reported `SOURCE_CHANGED` on T-01 and the evaluate session re-verified it before proceeding.
4. Existing fixture: kit update plus two user edits (commit `980fe3c`); the B1 prompt pre-authorized applying the migration when the preview showed no conflict.
5. Service scenario setup by the operator on both fixtures: `tools/local-service.cjs` started on a fixed port, `service.port`, PRD v2 and T-04 written by hand, `register --replace` (runtime) or nothing (baseline), T-04 verified and closed while the service answered, commits, then the service stopped and a failing `verify` run by the operator. A first B2 session was run before the operator's failing verify (nothing had failed yet); the agent correctly reported T-04 ready and refused the restore; it was repeated as B2b after the failing verify.
6. (c) regressions and the failing operator `verify`; (d) the SIGKILL of the operator's `verify`.
7. One session (the first B2 attempt after A3) was cut off by the account's usage limit and repeated once the limit reset.
8. No permission prompts (`bypassPermissions`); the kit hooks were active in every session.

## Findings

1. **`register` did not ignore `.pincer/`** (fixed as T-43 during the trial). After
   `Register PRD v1` and the first `verify`, `git status` showed `?? .pincer/`; the
   evaluate playbook's clean-tree rule would have refused. Registration, migration and
   the installer now add the line; the kit was re-packed and the fixture updated before
   A4.
2. **A kit update is a source change.** Updating the runtime files inside an evaluated
   project made every done ticket's attempt stale (`SOURCE_CHANGED` naming
   `scripts/pincer-runtime/…`). That is the contract working as designed, but a kit
   update on a project mid-flight costs a re-verify of every done ticket; the
   README's update notes should say so.
3. **Operator error is visible in the record.** The first service session ran before the
   failing verify; the agent's honest "nothing failed, nothing to restore" answer is
   kept in `trial-logs/B2-service.log` and the scenario was repeated as B2b.
4. **Wording slip in A7.** The resume session's summary says it "stamped a fresh
   receipt"; on a migrated project no receipt exists and the record shows attempt 18
   `passed` instead. The action was right, the description used legacy vocabulary.
5. **The baseline's friction is exactly the one PRD v4 targets.** Both kits refused to
   restore receipts; only the baseline needed a receipt-refresh commit after a repaired
   regression and left a ticket diff after an environmental failure.
