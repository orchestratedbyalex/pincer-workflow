# distribution-channels

One repo, three ways in. All feed from [[template-kit]].

## 1. npm / npx (universal)

`npx pincer-workflow init` — the primary channel, works for all three
platforms. Package contents: `bin/` + `template/` only (`files` in
package.json; `plugin/`, `test/`, wiki excluded). Publishing requires 2FA.
Release flow: edit template → run both generators → `npm version patch` →
`npm publish` → `git push --follow-tags`. Users update with
`npx pincer-workflow@latest update` ([[cli-installer]], [[never-clobber-updates]]).

## 2. Claude Code plugin (Claude-native)

`/plugin marketplace add orchestratedbyalex/pincer-workflow` then
`/plugin install pincer@pincer-workflow`. Root `.claude-plugin/marketplace.json`
makes the repo itself the marketplace; `plugin/` is generated by
`scripts/build-plugin.sh`: commands renamed into the `/pincer:` namespace
(plan.md → `/pincer:plan`), repo paths rewritten to `${CLAUDE_PLUGIN_ROOT}`,
hook wired via `plugin/hooks/hooks.json`. Auto-updates via marketplace.
The perl rename uses a negative lookbehind `(?<![\w/.])` so file paths like
`commands/pincer-plan.md` are NOT rewritten — only slash-command mentions.

## 3. Raw files (fallback)

Clone/copy the repo, read `template/` directly. Any agent can follow the
playbooks as plain markdown.

## Channel guidance (documented in README)

One channel per project for Claude users: plugin = global + auto-updating;
npx = project-local + repo-side files (AGENTS.md, deny rules, Codex/Copilot
adapters). Both at once → duplicate commands.

## Enforcement parity

Mechanical guardrails (deny rules + hook) exist on Claude Code only. Codex:
sandbox + approval policy (documented in `template/.codex/README.md`).
Copilot: tool-approval settings. Everywhere: /pincer-release audits git
artifacts after the fact — platform-independent by design.
