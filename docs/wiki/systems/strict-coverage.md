# Strict coverage

How a change proves it covered every requirement it agreed to. Added by PRD v6
(T-66..T-78, branch `feat/prd-v6`); opt-in per change, on top of the v5 change
lifecycle ([[explicit-change-lifecycle]], [[runtime]]).

## The chain

1. **Inventory** — `requirements.cjs` parses the PRD's own prose: a `##`..`####`
   heading `R-NN — Title`, bold `- **S-NN:** text` items under it, continuation lines
   indented. Mentions in prose, tables and fenced blocks define nothing. The parsed set
   is the obligation; there is no second editable list of requirements.
2. **Map** — `.prd/coverage/<change>.json` (schema 1) is the one authored file:
   scenario → tickets and checks, scope dispositions, ticket roles, and the declaration
   of every candidate check (a command with its timeout and cwd, or a review/visual
   obligation). `coverage.cjs` validates it and computes a declaration digest per check.
3. **Agreement** — the projection (version 2) gains `inventory` and `coverage` lines, so
   editing links, scenario text, a check command or a disposition changes the digest and
   invalidates the authorization. Snapshots (schema 2) retain the normalized inventory
   and map behind each agreement.
4. **Coverage** — `phases.cjs` computes three separate things: *structure* (every
   in-scope scenario linked, dispositions authorized, no deleted obligation), *implementation*
   (each linked ticket done and ready under the v5 rules) and *candidate* (the evaluated
   evidence). Completion needs structure; it never demands candidate evidence.
5. **Checks** — strict `check C-NN --candidate <sha>` runs the map's declaration and
   nothing else. A supplied command or timeout, an unknown id or a review obligation is
   `CHECK_UNDECLARED` (exit 4) before anything is prepared, and the declaration is
   recomputed under the attempt lock.
6. **Evidence** — manifest schema 3. The export *derives* every scenario and requirement
   row from the map snapshot and the outcomes; the author supplies only the reviews, the
   `adequacy` judgment and the environment. It writes the inventory and map snapshots as
   listed artifacts and computes `delivery` (original versus agreed scope).
7. **Reports** — `coverage` and `impact` are read-only, versioned (JSON schema 1 each),
   and feed the `Coverage` line in status (JSON schema 3) and resume (JSON schema 2).

## Invariants worth keeping

- Structure is not meaning. The runtime reports whether links exist; whether a check
  really establishes its scenario is the reviewer's `adequacy` verdict, recorded in the
  evidence and never computed.
- Nothing becomes strict implicitly. `coverage adopt --preview` writes nothing;
  `--apply` is one transaction (backup, schema 3 record, adoption snapshot) and grants
  no authorization. A project that never adopts sees schema 2 behaviour unchanged, and
  `coverage` labels it `unverified`.
- Dropping an obligation costs a decision *and* an authorization naming that decision.
  A generic "continue" authorizes no revised scope — the live runs in
  `docs/trial-prd-v6.md` show both arms being asked and mostly refusing.
- Old runtimes must refuse, not misread: v0.5.0 rejects evidence schema 3 and schema 3
  records outright ([[evidence-validator]], [[distribution-channels]]).

## Gotchas

- The authorization gate fires *before* the coverage gate: editing the map changes the
  agreement, so `change complete` says `AGREEMENT_CHANGED` first and `COVERAGE_INCOMPLETE`
  only after re-authorization. `docs/prd-v6-artifacts/replay.sh omitted` walks it.
- A `removed` tombstone must name the prior agreement (`prior: "G-NN"`); `deferred` may
  leave it null. Removing a scenario can orphan its ticket, which then has to be
  reclassified `enables` with a rationale or the structure stays incomplete.
- The fresh-clone allowance (a done ticket with no local attempt is a stated limit, not
  unfinished work) applies only to a *completed* change. Before completion the v5 rule
  holds: a clone must verify.
- A candidate evaluated before adoption has no `delivery` figures; the coverage summary
  line prints "delivery not recorded (evidence predates strict coverage)".

Representative artifacts of every one of these shapes live in
`docs/prd-v6-artifacts/records/`, generated by driving a scratch project through the
whole flow. The eight executable review cases are `docs/prd-v6-artifacts/replay.sh`.
