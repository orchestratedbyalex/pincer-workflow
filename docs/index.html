PINCERPINCER

The harness builder for AI coding agents

PINCER reads your repository, interviews you, and writes the agreement your agent works under. Then it runs the pipeline that agreement describes. For the repo you start today, and for the one with ten years of history.

npx pincer-workflow@latest init --platform all

Works in Claude Code, Codex CLI and GitHub Copilot. One kit, no dependencies.

Then it interviews you, one question at a time.

Six sections. What it already saw comes back as “I see X; is that right?”, and open is always an allowed answer.

Systems

Test: I see npm test running in GitHub Actions. Where is it done, and where does its record end up?

Locally and in CI. The record is the Actions run on the pull request.

Current pipeline

Think of the last real change that shipped. Walk me through it, from the moment it was asked for to the moment it was done.

An issue, a branch, a pull request, one review, squash, deploy on merge.

Handoff artifacts

Evidence, the logs and manifest showing the checks ran: kept under evidence/, or skipped because the pull request’s checks are the evidence?

The agreement names a tier for each stage and review agent, never a vendor’s model. One table maps tiers to each platform’s models, and update carries a new model into every project.

Build your harness.

  1. npx pincer-workflow@latest init --platform all
  2. Start your agent in the repository.
  3. Run /pincer-blueprint in Claude Code or Copilot, $pincer-blueprint in Codex CLI.

Node.js 22 or newer, git and bash. No provider API key. MIT licence. PINCER 1.0.4 is the current release; the same package is attached to the GitHub release. Coming from 0.7? It is a new agreement, not a silent migration: read the changelog first.
