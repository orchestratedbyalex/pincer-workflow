01 / Start with the agreement

A blueprint before the work.

Run /pincer-blueprint in Claude Code or Copilot, or $pincer-blueprint in Codex. It inspects the project, asks one question at a time, and confirms what it found with you.

The resulting harness.json and agreement in AGENTS.md define the stages, artifacts, review roster and people who accept the work. Open questions stay open.

02 / Keep the stages you need

One agreement. A configurable pipeline.

Plan & narrow

Turn a brief into requirements and tickets with runnable checks. Choose local artifacts or a forge-based workflow.

Code & evaluate

Implement tickets, verify them, and review the result with the agreed roster. Retain evidence when the agreement calls for it.

Release & status

Audit the result and record a named person’s acceptance. Status reads the files and names the next command.

Blueprint and status are always available. Other stages follow the agreement; a disabled stage refuses to run.

03 / A floor that stays in place

Completion is checked. Acceptance is human.

  • Verify before done: the ticket script runs the Verification block and stamps a receipt only on success.
  • Acceptance in your words: a person named in the agreement accepts a completed ticket.
  • State in files: a new session can inspect progress without relying on chat history.
  • Model tiers: choose strong, standard, fast or the session’s model for stages and agents. Inspect the platform mapping with doctor.

Claude Code has a hook for lifecycle guardrails. Codex and Copilot use standing instructions and status checks alongside their native controls. These mechanisms do not replace a sandbox or human review.

04 / Install the release

Try the 1.0 kit in a project.

Requires Node.js 22 or newer, git and bash. Use your coding tool’s own authentication; PINCER does not require a provider API key.

Install the stable release from npm in your project:

npx pincer-workflow@latest init --platform all
bash scripts/pincer-status.sh

Start your coding tool in that project and run the blueprint:

/pincer-blueprint     # Claude Code or GitHub Copilot
$pincer-blueprint     # Codex CLI

PINCER 1.0.0 is live on npm. A downloadable package is also available from the GitHub release. The Claude Code plugin channel is paused.

05 / Upgrading from 0.7

A new agreement, not a silent migration.

1.0 replaces the old runtime and fixed PRD workflow with the harness builder. Trial it in a separate checkout first. Preserve your old tickets, evidence and edited files; they do not become 1.0 verification or acceptance records automatically.

The old wiki and PRD-v8 study documents remain historical. See the release notes and upgrade guidance before updating an existing project.
